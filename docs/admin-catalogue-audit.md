# Admin and catalogue audit

This audit is based on repository code and the local environment inspected for this task. The storefront was preserved; this is an extension of the existing Express/Mongoose and Next.js implementation.

| Question                     | Finding and resulting behavior                                                                                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Does admin exist?            | Yes: existing responsive shell/sidebar, dashboard, role gates, inventory, orders, settings and other operations screens. Products was a limited inline create form; category/collection pages were placeholders. Those catalogue workflows are now implemented in the existing shell.                                                                                                                                                                         |
| Exact admin URL?             | `http://localhost:3000/admin`                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Exact login URL?             | `/admin/login` added using existing authentication; `/auth/login` remains valid.                                                                                                                                                                                                                                                                                                                                                                              |
| Does authentication work?    | Existing Argon2 password authentication, JWT access tokens, refresh/CSRF cookies and API RBAC are retained. Fixed Mongoose role-array serialization before signing JWTs. Added a refresh single-flight guard to avoid concurrent token rotation invalidating a session. Bootstrap forces initial password change.                                                                                                                                                                                                          |
| Products page?               | `/admin/products`, with pagination, search, status actions and links to `/admin/products/new` and `/admin/products/[id]/edit`.                                                                                                                                                                                                                                                                                                                                |
| Create/edit/publish/archive? | API already had these operations. Fixed frontend `/catalog/admin/...` calls to actual `/admin/...` paths and connected the UI. Archive is supported instead of destructive product deletion.                                                                                                                                                                                                                                                                  |
| Fields?                      | Copy, slug, images, category, collection, audience, fit, material, care, per-variant colour/size/SKU, MRP, sale price, stock, threshold, status, featured, new arrival and SEO are supported. Ratings and sales claims cannot be fabricated in admin.                                                                                                                                                                                                         |
| Storefront source?           | MongoDB via `/api/v1/catalog/products`, facets and detail endpoints. Homepage editorial content can fall back locally; product rails do not invent static products.                                                                                                                                                                                                                                                                                           |
| Why no visible products?     | The original product admin requested nonexistent endpoints. Base seed contains no products. Global Mongoose `sanitizeFilter` also broke internal operator queries and prevented seeding. No MongoDB/Redis was listening locally; the API environment had no `PRODUCT_PREVIEW_SECRET` and several empty/duplicate values. The web can render editorial fallback imagery when API calls fail. A successful bootstrap/seed alone does not publish real products. |
| Demo data?                   | Existing safe opt-in seed: 12 labelled demo products, 48 approved local images, active variants and sample stock. No fake reviews. The existing seed was repaired and scoped to 12 products for fresh local databases; earlier seeded products are not deleted.                                                                                                                                                                                               |
| Admin bootstrap command?     | `pnpm --filter @thread/api bootstrap:admin`; requires `MONGODB_URI`, `ADMIN_BOOTSTRAP_NAME`, `ADMIN_BOOTSTRAP_EMAIL`, `ADMIN_BOOTSTRAP_PASSWORD`, `ADMIN_BOOTSTRAP_CONFIRM=CREATE_THREAD_SUPER_ADMIN`. Now idempotent for the same active super administrator, rejects conflicting accounts, closes connections on failure and never hard-codes credentials.                                                                                                  |
| Required environment?        | See the exact API/web matrix and commands in [local development](local-development.md). Cloudinary is required only for new image uploads. MongoDB must be a replica set; Redis powers jobs/realtime.                                                                                                                                                                                                                                                         |

## Verification

See the task's final report for completed checks. Automated coverage includes bootstrap validation, product input rules, existing auth/catalogue suites and `e2e/product-management.spec.ts` for admin login, taxonomy creation, product/variant persistence, draft visibility, publication across storefront pages and archival. E2E bootstrap runs twice to exercise idempotency. The E2E fixture now selects an actual seeded product rather than an archived legacy slug and uses the real detail-response shape.
